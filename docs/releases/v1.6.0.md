# OCI HPC Trial Pack v1.6.0

## 追加・改善内容

- Autoscaling の作成が連続して失敗した場合、新規作成を停止する機能を追加しました。全キュー共通で既定3回、`autoscaling_failure_threshold = 0` で無効にできます。実行中ジョブ・開始済みの作成・既存クラスターの安全な削除は継続します。
- `autoscaling_guard.py status` / `resume` による日本語の状態確認・手動再開と、既存の管理者通知を使った停止・復旧メールを追加しました。通常の成功は通知せず、失敗後の作成成功で復旧を通知します。
- 作成失敗の終了コードを正しく返すよう修正し、停止中のログ表示と失敗回数の診断を改善しました。

## 既存環境を更新する場合

Resource Manager の構成ZIPを更新し、Plan で両 Controller へのプログラム配布と設定変更を確認してから Apply してください。今回の機能による計算リソースの置換は意図していませんが、Plan の実際の変更対象を確認してください。

既定で3回の連続失敗後に自動作成が停止します。保存済みの値が `0` の場合は無効のままなので、利用する場合は回数を指定してください。停止後は原因を解消し、管理ユーザーで `/opt/oci-hpc/bin/autoscaling_guard.py resume` を実行します。管理者通知は従来どおり既定で無効で、停止判定とは独立しています。HA の状態は Controller ごとに管理し、相互同期しません。

## 検証

ローカル回帰テストは674件、失敗0件・スキップ3件でした。スキップは任意の Ansible role 実行テスト、Terraform 1.7 以降を要するモックテスト、追加 Ruby gems を要する実行テストです。Terraform 1.5.7 の構成検証、書式検査、Shell 構文検査、Python 3.6 の構文互換性検査も成功しました。旧版の基本動作は利用者から成功報告がありますが、今回の最終版の OCI / Slurm 上での実環境確認は未実施です。[基本テスト手順](../autoscaling-guard-basic-test.md)を参照してください。

添付の `oci-hpc-trial-pack-v1.6.0.zip` は、Terraform の構成ファイルをZIP直下に配置し、`.git` を含みません。
