# OCI HPC Trial Pack v1.4.4

v1.4.4 は、Autoscaling の計算ノード作成失敗を管理者へ通知する機能と、軽量版計算ノードの timezone 修正、OL8 Custom Image の既定値更新をまとめたリリースです。作成失敗通知は既定で無効です。

## 作成失敗の原因を保存して管理者へ通知

`autoscaling_failure_notifications_enabled=true` と通知先の `autoscaling_failure_admin_email` を指定すると、Slurm ジョブ通知とは独立した OCI Notifications Topic / EMAIL Subscription を作成します。Subscription の確認メールを承認してから利用してください。

Autoscaling クラスターの作成に失敗した場合、強制削除による後始末の前に診断を保存します。Ansible の失敗では task・host・理由を抽出し、インスタンス作成の失敗では特定できた OCI Work Request の error・log を収集します。メール冒頭の `Failure phase` はログの根拠から判定し、根拠がない場合は判定不能と表示します。セットアップ失敗では Work Request の取得・表示を省略します。

Cluster Network の作成失敗では、親に加えて所属 Instance Pool の失敗 Work Request も確認します。所属は API のリソース ID で照合し、同名の別 Pool は採用しません。OCI 情報を取得できない場合も、作成ログの原因を残します。

送信に失敗した通知は Controller 上に保持し、cron で再送します。送信失敗は既存の後始末を停止させません。Python 3.6 に対応する subprocess 引数を使い、PATH に OCI CLI がない場合はユーザーとシステムの配置先を探索します。

通知用 Dynamic Group と IAM Policy はホームリージョン、Topic と Subscription はデプロイ先リージョンに作成します。課金タグ・通常の IAM 自動作成・Slurm ジョブ通知をすべて無効にしても、作成失敗通知が有効ならホームリージョンを取得します。これにより、ホームリージョン以外へのデプロイで通知用 Dynamic Group の作成が `403-NotAllowed` になる不具合を修正しました。

## 軽量版の新規計算ノードにも timezone を適用

軽量版 Autoscaling の playbook に timezone ロールを追加しました。通常版と同様に、スタック変数 `timezone` を Slurm の構成前に適用します。既定値は `Asia/Tokyo` で、別の値も使用できます。

Controller の OS で手動変更した timezone を取得する機能ではありません。稼働中の計算ノードには自動適用されず、更新後に新しく作成するノードが対象です。

## OL8 Custom Image の既定値を v1.4 に更新

SIMPLE / ADVANCED のインポート用 URL・表示名を `oci-hpc-v2.10-compute-image-v1.4` に揃えました。SIMPLE モードで事前構成済みイメージを選んだ場合は Controller にも使用します。イメージの v1.4 は Trial Pack 本体の v1.4.4 とは独立した番号です。

## 既存スタックの更新

1. Resource Manager の既存スタックを、このリリースの構成 ZIP に更新します。Release 添付の `oci-hpc-trial-pack-v1.4.4.zip` は、Terraform のルートファイルを ZIP 直下に配置し、Git 履歴や Python キャッシュを含めていません。
2. 通知を使用する場合は有効化フラグと専用宛先を設定します。ADVANCED モードで保存済みの OL8 イメージ URL・表示名が v1.3 の場合は、v1.4 の値に変更します。
3. Plan で IAM・Topic・Subscription・通知プログラム配布の変更と、イメージ・ノードの置換対象を確認してから Apply します。ホームリージョンエラーで途中停止したスタックも、作成済みリソースを確認したうえで既存スタックを更新します。
4. 軽量版の既存 Controller では `/opt/oci-hpc/playbooks/lite_new_nodes.yml` と、実際に実行される `/opt/oci-hpc/playbooks/new_nodes.yml` に timezone 修正を反映します。構成 ZIP の差し替えだけで、既存 Controller の全ファイルが再配布されたと判断しないでください。

旧通知プログラムだけを手動更新する場合は、`bin/autoscaling_failure_notify.py` を `/opt/oci-hpc/bin/` に配布します。Topic・IAM・設定ファイル・cron はスタックの更新対象なので、このファイルだけの配布では通知機能は有効になりません。

Python 3.6 の `capture_output` エラーで保存前に停止した試行は、プログラムを更新しても自動再送されません。保存済みの作成ログから改めて診断を行う必要があります。通知を無効にすると Terraform が専用 Topic・Subscription・IAM を削除し、再送 cron を停止するため、未送信ファイルを確認してから変更してください。

イメージの既定値更新は稼働中ノードの OS を直接更新しません。既存スタックでイメージ入力を変更すると、登録済みイメージやノードの置換につながる可能性があります。

## 検証結果と確認範囲

Ubuntu のホームリージョンエラー修正後、利用者から現状の動作確認完了報告を受けています。OS バージョン・構成・個別シナリオの内訳は報告されていないため、HA や全作成方式、通知の全失敗・再送経路の確認完了を示すものではありません。

ローカル検証では、3ブランチ統合時に Python テスト596件を実行し、594件成功・2件スキップでした。スキップは `TERRAFORM_BINARY` の指定を必要とする検証です。最後のホームリージョン修正をマージした後は、通知・設定経路・timezone の関連テスト52件がすべて成功しました。OCI 呼び出しはモックまたはコマンドスタブであり、実際の通知配信を確認するテストではありません。

Terraform 1.5.7 の `validate`、変更した Shell と軽量版 Ansible playbook の構文確認、OL8 イメージ既定値の3箇所の一致、差分の空白検査も成功しています。ホームリージョンを IAD、デプロイ先を大阪とする provider 不要の Terraform 検証で、4機能フラグの全16通りの選択結果を確認しました。

Terraform の書式検査は、通知用の2ファイルで成功しています。`controller.tf`・`locals.tf`・`variables.tf` の既存の書式差分は保持しています。実環境で確認する項目は [回帰確認台帳](../REGRESSION_LEDGER.md)の REG-013 / REG-015 / REG-028 / REG-029 を参照してください。
