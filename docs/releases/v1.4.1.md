# OCI HPC Trial Pack v1.4.1

v1.4.1 は、Open OnDemand のジョブ管理メニューを整理し、OpenComposer の履歴を確認・更新しやすくしたパッチリリースです。開始・終了時刻の表示を揃え、Intel MPI を TCP で使うジョブの生成オプションも修正しました。

## ジョブの投入と履歴確認を「03 ジョブ管理」に集約

従来の「04 OpenComposer」を「03 ジョブ管理」に変更し、「Slurmジョブ」と「History」を同じメニューにまとめました。ジョブの投入と確認は OpenComposer から行います。

OOD 標準の「ジョブ投入」と「Active Jobs」はトップ画面・ヘッダーメニュー・All Apps から非表示にしました。Project Manager と Module Browser もメニュー・All Apps から非表示にし、項目がなくなった親メニューは表示しません。ファイル操作、ブラウザシェル、System Status、VNC／DCV、対話型セッションは引き続き利用できます。

非表示にしたアプリ本体と既存データは保持します。メニューからの非表示は、直接 URL へのアクセスを禁止する設定ではありません。

## 履歴で実行時間を確認し、条件を保ったまま更新

History に次の項目を追加しました。

| 表示項目 | 内容 |
| --- | --- |
| Start Time | ジョブの開始時刻 |
| End Time | ジョブの終了時刻 |
| Elapsed Time | ジョブの経過時間 |
| CPU Time | 経過時間と割り当て CPU 数の積（Slurm の `CPUTime`） |

開始・終了時刻は、投入時刻（Submission Time）と同じ `YYYY-MM-DD HH:MM:SS` 形式で表示します。CPU Time は実際に消費した CPU 時間の合計（`TotalCPU`）とは異なります。未開始・未終了の値や空欄は保持し、保存済みの会計情報に時間項目がない過去の履歴は空欄になります。

`Refresh` ボタンで、検索条件・並び順・ページを保ったまま履歴結果を更新できます。検索欄に入力中の未適用の文字と、更新後も残っている行の選択を保持します。更新後のキャンセル対象は最新のジョブ状態で判定し、更新に失敗した場合は元の表を残してメッセージを表示します。

## Intel MPI の TCP プロファイルを修正

OpenComposer の `VM (TCP)` と `BM Standard (TCP)` で Intel MPI を選択した場合、生成する `MPI_OPTIONS` に `-genv I_MPI_COLL_EXTERNAL 0` を追加しました。他の MPI 実装や `BM HPC (RDMA)` のオプションは維持します。

## 既存環境には Open OnDemand role を再適用

既存コントローラへ v1.4.1 の `playbooks/roles/openondemand/` 全体を配布し、[OOD 専用 playbook の実行手順](../openondemand-4.2.5-upgrade.md#更新した生成元で-ood-専用-playbook-を実行する)に従って再適用してください。新しい設定・履歴ビュー・JavaScript・ジョブフォームを配布し、変更時にダッシュボードと OpenComposer の再起動を要求します。適用後はブラウザを再読み込みしてください。

既存の履歴 DB とジョブスクリプトは保持します。リリースの公開や Resource Manager の構成 ZIP の差し替えだけでは、既存コントローラ上のファイルは更新されません。Open OnDemand 4.2.5、Dex 2.45.1、OpenComposer v2.0.2 の固定バージョンは変更しません。

## 検証結果と確認範囲

利用者から、今回の変更を含む `master` のテスト完了報告を受けています。OS・構成・個別シナリオの内訳は報告されていないため、すべての環境・更新経路の検証完了を示すものではありません。

公開前のローカル関連回帰テストは46件すべて成功し、スキップはありませんでした。メニュー設定のレンダリング、履歴ビューの Ruby ERB レンダリング、Refresh の JavaScript 動作、MPI オプションの生成、OOD 更新処理を確認しました。OOD 専用 playbook の構文確認、文書リンク確認、`git diff --check` も成功しています。実 Slurm との会計情報の照合やブラウザ操作の確認項目は、[回帰確認台帳](../REGRESSION_LEDGER.md)の REG-008 / REG-009 / REG-027 を参照してください。
