# OCI HPC Trial Pack v1.3.0

v1.3.0では、計算ノードの名前をそろえる仕組み、AMD VMのHyperthreading（HT）制御、Slurmユーザー別のコストタグを統合しました。v1.2.0からの更新では、既存キュー・必要権限・タグ定義・DNS移行を確認してください。

## 1. OCIとOSで計算ノードの名前をそろえる

Instance Pool・Cluster Network・Compute Clusterの3方式で、Ansible構成後の実際のOSホスト名を取得し、OCIインスタンス名とPrimary VNICの表示名に反映します。SlurmやOSで見ているノードをOCI Consoleでも同じ名前で探せるようになります。

- 同期後の名前をDNS・inventory・監視情報・クラスター管理処理でも扱います。
- 再構成や同期が途中で失敗した場合は、記録に基づいて未完了の処理を再開します。
- VNICの`hostname_label`、Secondary VNIC、VNIC attachment固有の表示名は同期対象外です。
- 通常のAutoscalingは引き続きジョブに応じたクラスター単位の作成・削除です。既存クラスターの途中リサイズを通常運用として追加するリリースではありません。

## 2. AMD VMのHT設定を起動時に反映する

対応するAMD VMのInstance Poolで、キューの`hyperthreading`をOCIの起動構成へ渡し、初期ノードとAutoscalingノードのHTを制御します。Shapeが要求する設定に対応するかも確認します。

- AMD VMは対応情報が要求値を許容する場合にHT On / Offを指定します。
- Intel VMのHT Offは対象外です。`hyperthreading=false`はSlurm設定反映前に拒否し、Terraformでも作成前に検出します。Intel VMのHT OnはHT用platform_configを送らず、Shapeの既定設定を維持します。
- VMではOS側でCPUをオフライン化しません。ベアメタルの従来のBIOS / SMT制御は維持し、OS側スクリプトは`0-1`などのCPU範囲表記に対応します。
- キュー全体のHT値や`instance_keyword`の重複を検証し、不正な設定ではSlurmへの反映前に終了します。

## 3. Slurmの利用者をOCIコストタグへ反映する

Definedタグ`hpc-cost.User`を計算ノードに付け、Slurmの割当状態に合わせて更新します。1ジョブがノードを占有する運用を想定しています。

| ノードの状態 | `hpc-cost.User` |
| --- | --- |
| 作成直後・アイドル | `Management`（明示的な作成時タグ指定がある場合はその値が優先） |
| 1ユーザーが使用中 | Slurmユーザー名 |
| 複数ユーザーが共有 | このキーを除去し、1人に誤って帰属させない |

Prolog / Epilogは状態を記録し、コントローラーのワーカーが非同期にOCIへ反映します。再試行・排他制御・Slurmの現在状態との照合により、遅れた終了イベントで新しい利用者を上書きしないようにします。他のDefinedタグとfreeformタグはワーカーが保持します。新規ノードには複製元の実行中ユーザーを引き継ぎません。

## 既存環境を更新する際の注意

1. **Terraformとキュー設定を確認する。** 初期スタック・AutoscalingともTerraform 1.5.0以上が必要です。Intel VMのHT Offや不正なキュー設定は更新前に見直してください。
2. **IAMとタグ定義を準備する。** 名前同期にはPrimary VNICの更新権限が必要です。コストタグにはタグ定義の管理、テナンシ／ホームリージョン参照、コントローラーからのインスタンス更新とタグ使用権限が必要です。`slurm_user_tags_enabled=false`やIAM自動作成無効でも、タグ定義・作成時タグと必要な参照は残ります。
3. **既存の`hpc-cost`を確認する。** 同名の名前空間がある場合は管理元を確認し、必要な場合だけstateへ取り込みます。同じ定義を複数スタックで重複管理しないでください。このスタックが管理するタグ定義はdestroy対象になります。
4. **配布とplanを確認する。** Gitの更新だけでは稼働環境は更新されません。初期スタック、コントローラー・予備コントローラー・計算ノードの設定、Autoscaling用原本と変数生成元を更新対象として確認してください。Instance Configurationは新しい構成を作成してから旧構成を削除します。planで既存リソースへの影響を確認してください。
5. **既存クラスターの名前・DNSを移行する。** 更新したスクリプトで次の再構成を一度行います。既存Cluster Network / Compute Clusterの初回移行は、生成済みディレクトリでの直接の`terraform apply`ではなく、この経路を使用します。

   ```bash
   /opt/oci-hpc/bin/resize.sh --cluster_name <cluster_name> reconfigure
   ```

6. **既存VMのHTとタグを確認する。** Instance Configurationの更新だけで稼働VMのHTは変わりません。旧HTサービスでCPUをオフライン化したVMは、自動でCPUを戻さないため、ジョブ終了後に適切な設定で再作成してください。既存ノードのコストタグはワーカー有効時に現在の割当へ追従します。ワーカー無効時は必要に応じて既存ノードの初期値を設定します。
7. **費用集計の参照先を変更する。** freeformタグ`user`からDefinedタグ`hpc-cost.User`へ移行します。ワーカーは旧タグを更新しません。Terraform管理リソースでは旧タグを削除する差分が出る場合があります。新しいタグ適用前の費用は自動移行しません。

詳細は[README](https://github.com/kazuitox/oci-hpc-trial-pack/blob/v1.3.0/README.md)、[コストタグの設定・移行手順](https://github.com/kazuitox/oci-hpc-trial-pack/blob/v1.3.0/docs/slurm-user-cost-tags.md)、[HT制御の検証記録](https://github.com/kazuitox/oci-hpc-trial-pack/blob/v1.3.0/docs/vm-instance-pool-hyperthreading-feasibility.md)を参照してください。

## リリース範囲と確認

取り込んだブランチは次の5本です。

- `fix/instance-pool-hostname-sync`
- `fix/cluster-network-hostname-sync`
- `fix/compute-cluster-hostname-sync`
- `fix/vm-instance-pool-hyperthreading`
- `feature/slurm-user-cost-tags`

`fix/autoscale-safe-node-removal`は含みません。削除前のジョブ確認・DRAINによる保護は、独立した後続リリースで扱います。

各ブランチは利用者による動作確認済みとの報告に基づいて統合しています。今回のリリース作業ではローカルの統合回帰テスト・構文検証を行い、OCIへのapply / destroyや統合版での実機ジョブ試験は実施していません。動作確認の中心はOracle Linux 8です。

統合後の検証結果:

- Python回帰テスト：**456件成功、スキップなし**。AnsibleによるHT role実行テスト、Terraform 1.9.8によるHT mock plan、Rubyによる物理コア集計も含みます。
- Terraform 1.5.7 `validate`：初期スタックと、テンプレートから変数・providerを生成したAutoscaling構成の両方で成功。
- Ansible構文確認：`site.yml`、`new_nodes.yml`、`lite_new_nodes.yml`、`resize_add.yml`、`refresh_instance_pool_hosts.yml`で成功（ローカルの検証用inventoryを使用）。
- 変更したShellスクリプト7本の構文確認、テンプレート関連テスト、文書リンク確認、`git diff --check`：成功。
- `terraform fmt -check`：20ファイルで既存の書式差分を検出。すべてv1.2.0にも存在し、今回新たに不合格となったファイルはありません。全体整形はこのリリースに含めていません。
