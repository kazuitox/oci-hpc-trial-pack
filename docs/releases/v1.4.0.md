# OCI HPC Trial Pack v1.4.0

v1.4.0 は、課金タグの有効・無効を選べる機能を追加し、Open OnDemand と Autoscaling ノードの構成処理を更新したリリースです。v1.3.3 で発生し得た Slurm 初回起動、Ubuntu の LDAP・VNC、内蔵 NVMe のマウントに関する不具合を修正しています。

## 課金タグをデプロイ時に選択できる

`cost_tags_enabled`（既定値 `true`）を追加しました。Resource Manager の SIMPLE / ADVANCED 両モードで選択できます。無効時は `hpc-cost.User` の定義作成・初期付与・Slurm に応じた更新を行いません。Autoscaling のノード複製でも、既存の課金タグを初期化せず、所有権や一時 Block Volume の管理タグを維持します。

既存のタグ定義は Terraform の `moved` で state アドレスを引き継ぎます。`prevent_destroy` により、定義を管理済みのスタックで課金タグ全体を無効化する操作や、定義を含む `destroy` は停止します。更新だけを止める場合は `slurm_user_tags_enabled=false` を使います。削除する場合は、定義の管理元の引継ぎ、または削除保護の解除が必要です。詳細は [課金タグの運用手順](../slurm-user-cost-tags.md)を参照してください。

## Open OnDemand と Ubuntu のデスクトップを更新する

Open OnDemand を4.2.5、Dex を2.45.1へ更新し、Node.js 22を使用します。OOD のファイル転送に関する脆弱性 GHSA-frjp-qp79-hc3g の修正版を導入します。認証用の `oidc_crypto_passphrase` はコントローラで生成・保存して再利用します。旧版の標準 Ruby ファイルによる上書きを廃止し、OpenComposer の再実行と Ubuntu での導入も改善しました。

Oracle Linux 8 の新規構築で、Node.js の有効ストリームがないために確認タスクが停止する問題を修正しました。Ubuntu 24.04 の Xfce は専用 D-Bus セッションで起動し、起動スクリプトから終了コードを返します。VNC 計算ノードには `dbus-daemon` を導入します。

既存 OOD の更新では、認証設定・パッケージ・独自アプリを復旧できる状態にしてから [OOD 更新手順](../openondemand-4.2.5-upgrade.md)に従ってください。更新時に PUN（ユーザーごとの Web プロセス）を終了するため、Web セッションへの影響があります。

## Slurm 起動と Autoscaling の LDAP 処理を修正する

初回構築で `systemctl reset-failed slurmctld` が対象 unit の未読み込みを返した場合だけ、後続の起動へ進みます。権限エラーやタイムアウトは引き続き停止し、サービス起動・Slurm 応答の検査も維持します。

Ubuntu の通常版・軽量版 Autoscaling では、`fix_ldap` の対象を新規計算ノードに限定しました。クラスターの並行作成によって既存コントローラの SSSD を繰り返し再起動する経路を解消します。

## NVMe の LVM 構成を Ansible モジュールへ置き換える

localdisk ロールを Ansible の `lvg`・`lvol`・`filesystem`・`mount` モジュールによる構成へ置き換えました。LV 作成成功時の `--nosync` 警告を独自 Python スクリプトがエラー扱いし、XFS 作成とマウント前に停止する問題を解消します。

`localdisk=true`、`log_vol=true`、`redundancy=true` で、2台の NVMe は LVM RAID1、4台以上の偶数台は RAID10 として構成します。VG は `vg_nvmes`、LV は `lv_nvmes`、ファイルシステムは XFS、inventory のマウント先は `/mnt/localdisk` です。既存 LV は再利用し、サイズ・RAID 形式は変更しません。

既存環境には `tasks/`・`defaults/`・`filter_plugins/` を含む [localdisk ロール](../../playbooks/roles/localdisk/README.md)全体を配布してください。既存 LV の詳細な RAID 配置検査は旧スクリプトと異なり、参照ロールの所属確認と再利用方式になります。個別ディスクの fstab は UUID 指定になります。Autoscaling 計算ノードの localdisk 失敗は警告を記録して後続へ進むため、構築後にマウントを確認してください。

## 確認した範囲を区別する

公開前のローカル全件回帰テストは565件、失敗0件、スキップ21件でした。localdisk 関連は42件、失敗0件、スキップ3件です。Ansible の localdisk 構文確認、文書リンク確認、`git diff --check` も成功しました。スキップには Ansible 実行環境の指定や Terraform が必要な検査が含まれます。localdisk の3件は macOS 環境に `blkid`・`parted` がないためです。ローカル検証は OCI 上の動作確認とは区別しています。

利用者から、今回統合した各ブランチの動作確認完了報告を受けています。個別に確認できた範囲は、Ubuntu 24.04 の Xfce / VNC 接続、課金タグを無効にしたデプロイでの Slurm 起動、BM.Standard.E6.Ax.192 の Autoscaling ノードでの NVMe 論理ボリュームの `/mnt/localdisk` へのマウントです。NVMe は約894GiBの容量でマウントされた出力を確認しました。

これらの報告は、HA、RAID10、すべての OS・イメージ・更新経路の検証完了を示すものではありません。実環境の追加確認は [回帰確認台帳](../REGRESSION_LEDGER.md)の REG-016 / REG-021 / REG-024 / REG-025 / REG-026 に沿って実施してください。

Autoscaling 作成失敗メール通知の `feature/autoscaling-failure-notification` は本リリースに含みません。既存スタックは、リリース公開や構成 ZIP の差し替えだけではコントローラのファイルが更新されないため、配布と再構成を別途行ってください。
