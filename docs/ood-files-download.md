# Filesでフォルダ構成を保ってZIPなしで保存する

Open OnDemand 4.2.5のFilesに「Download（ZIPなし）」を追加する。複数のファイルやフォルダを選び、手元の保存先を指定すると、その中へ階層を保って保存する。サーバーでのZIP作成と、保存後の展開が不要になる。

この変更はローカルの処理テストで確認している。実際のOOD画面とOCI環境での受入確認は未実施。導入担当者は末尾の確認項目を実施してから利用を案内する。

## 利用者が保存先を選んで取得する

HTTPSでOODに接続し、ChromeまたはEdgeなど、保存先フォルダへの書き込みに対応したブラウザを使う。SafariやFirefoxなど未対応の環境では、対応ブラウザへ切り替えるか、従来のDownloadを使う。[ブラウザの保存機能の仕様](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)を参照。

1. Filesで保存したいファイルやフォルダを選択する。
2. 上部の「Download（ZIPなし）」を押す。
3. ポップアップで容量の計算が始まる。計算中は回転するアイコンが表示され、名前欄と保存先選択は表示しない。「キャンセル」は最初から利用できる。
4. 計算後に合計サイズ・ファイル数とフォルダ名欄が表示される。名前を確認・変更して「保存先を選択」を押し、手元の保存先を選ぶ。ブラウザから書き込み許可を求められたら許可する。
5. 同じポップアップ内に、転送中のファイル番号／総数と平均転送レートが表示される。転送中も「キャンセル」で中止できる。
6. 「保存完了」を確認し、「閉じる」で戻る。保存先に作成されたフォルダを確認する。転送中はFiles画面を開いたままにする。

単一・複数選択ともポップアップには「合計サイズ: 1.50 GiB（100ファイル）」の形式で表示する。フォルダは配下を確認して集計し、フォルダ自体はファイル数やサイズに加算しない。確認中は「合計サイズを計算中…」と回転するアイコンを表示し、名前欄と保存先選択を隠す。権限やサイズ制限などで確認できない場合は理由を表示し、保存を開始しない。キャンセルすると確認中の通信も中断する。表示値は確認時点のファイルサイズの合計で、保存先のディスク使用量や転送後の実測値を保証するものではない。

転送中は同じポップアップ内に「1/100ファイルをダウンロード中 · 12.4 MiB/s（平均）」の形式で表示する。ファイル名は表示しない。総数は配下のファイルだけを数え、空フォルダは含めない。レートは転送開始からの平均で、通信待ちと保存先への書き込み時間を含む。

単一フォルダ `results` を取得すると、保存先に `results/` を作り、その直下へ元の内容を保存する。`results/results/` のように二重にはしない。

複数のファイルやフォルダを選択した場合は、入力した名前のフォルダの中にまとめる。ポップアップの名前の初期値は `download`。通常ファイルを1件だけ選択した場合も同じポップアップを使う。単一フォルダの初期名は元のフォルダ名で、必要に応じて変更できる。同名の保存用フォルダがある場合は `results-1`、`results-2` のように連番を付ける。既存ファイルの上書きは行わない。

計算開始から転送終了まで、ポップアップの「キャンセル」で中断できる。Escでも同じように中断する。完了・エラーはポップアップ内に表示し、「閉じる」で戻る。ポップアップを閉じた後やキャンセル後に、完了・中止メッセージを画面上へ残さない。空のメッセージ欄も表示しない。途中で通信エラーや認証切れが発生した場合も停止し、完了済みのファイルは保存先に残す。失敗したファイルが空のまま残る場合があるため、途中の結果を全件取得済みと扱わず、再実行後の新しい保存先を使う。自動再開と差分同期は行わない。

従来の上部ボタンは「従来のDownload（フォルダはZIP）」という表示で残す。行ごとのメニューのDownloadも従来の動作を維持する。4.2.5の標準実装では、通常ファイルは個別に、フォルダはZIPで取得する。

## 対象と制限を確認する

ZIPなし保存は、ホームや共有領域など、Filesの通常のファイル領域（`fs`）が対象。外部リモートストレージは対象外とする。シンボリックリンクが選択範囲にある場合は、一覧の確認段階で停止する。リンク先の取得やリンクの再作成は行わない。

既存のOOD認証、サーバー側のアクセス権と許可パス、ダウンロード有効・無効設定、ファイルサイズ制限を利用する。フォルダは既存APIでサイズと確認処理の時間制限も検査する。読み取りできない項目を検出した場合は停止する。Files側で一覧から除外される項目は取得しない。

1回の選択はファイルとフォルダを合計して最大10,000件、フォルダ階層は64階層未満。これを超える場合は選択範囲を分ける。ローカル側で大文字・小文字だけが異なる同名項目などが衝突する場合は、上書きを避けるため停止する。保存先OSで使用できない名前もエラーになる。

ファイルは1件ずつストリームで書き込み、全体をメモリへ読み込まない。転送前の一覧と転送データのサイズが異なる場合は失敗にする。更新中のファイルは避け、ジョブ完了後などに取得する。同じサイズでの内容変更を検出するチェックサム照合や、転送対象のスナップショットは行わない。ファイル内容と名前・階層を保存し、所有者・UNIX権限・更新時刻は複製しない。解凍時間はなくなるが、多数の小さいファイルでは個別の通信に時間がかかる場合がある。

## 容量確認は最上位フォルダごとに300秒まで待つ

Ansible roleの `ood_download_dir_timeout_seconds` の既定値を300秒とし、`/etc/ood/config/ondemand.d/ondemand.yml` に `download_dir_timeout_seconds: 300` を生成する。この設定は、ZIPなし保存と従来のZIPダウンロードが利用する標準の容量・制限確認に適用される。容量確認が早く終われば、その時点で次へ進む。転送そのものの時間制限ではない。

ZIPなし保存では、選択した最上位フォルダごとに標準の容量・制限確認を1回だけ行う。この確認は配下を含むため、子フォルダで同じ確認を繰り返さない。子フォルダは一覧取得とサイズ集計を行い、権限エラーなどがあれば停止する。ファイルごとのダウンロード制限も引き続き適用する。

300秒は各最上位フォルダの標準確認の上限であり、計算全体の上限ではない。複数フォルダでは全体が5分を超える場合がある。ブラウザ側の通信タイムアウト、自動再試行、途中再開は追加していない。キャンセルでブラウザ側の通信は中断するが、すでに実行中のサーバー側の容量確認が即時停止することまでは保証しない。

既存環境で `OOD_DOWNLOAD_DIR_TIMEOUT_SECONDS` を環境変数に指定している場合は、生成したYAMLより環境変数が優先する。導入時に実効値を確認する。また、Apache・Nginx・ロードバランサーで、容量確認の応答を待つ時間が300秒より短く設定されていないか確認する。必要な待機時間は処理時間に通信の余裕を加えて決める。これらの稼働中の設定確認と、5秒を超える容量確認の受入試験は未実施。

## 導入担当者が既存環境へ反映する

更新した `playbooks/` をコントローラへ配布し、既存のinventory・変数を使って `playbooks/openondemand.yml` を再実行する。TerraformのApplyや計算ノードの作り直しは、このFilesの変更には不要。既存のResource Managerスタックでは、構成ZIPを差し替えるだけではAnsibleが再実行されないため、コントローラへの配布とplaybookの再実行を行う。

roleは `/etc/ood/config/apps/dashboard/views/files/_download_button.html.erb` と、`/var/www/ood/public/files-direct-download.js` を配置する。変更時はPassengerの再起動を要求する。新たなサービス、IAM権限、ポートの追加はない。反映後はOODの画面を再読み込みする。独自の同名ビュー上書きがあるサイトでは、適用前に差分を確認する。

ZIPなし保存の追加を取り消す場合は、追加した上記2ファイルを削除し、DashboardのPassengerを再起動する。上書き済みの独自ビューがあった場合はそのバックアップを戻す。追加処理を含むroleを再実行すると再配置されるため、配布元の版も合わせて戻す。

## ボタンが反応しない旧版から更新する

初版は `/public/files-direct-download.js` を読み込むビューに対して、スクリプトを `/var/www/ood/apps/sys/dashboard/public/` に配置していた。OODの標準設定では `/public/` は `/var/www/ood/public/` に対応するため、クリック処理を読み込めなかった。修正版は公開先に合わせて配置し、読み込み完了までボタンを無効にする。読み込み中の表示が続く場合は、スクリプトの配布状態と公開URLの応答を確認する。

旧版を適用済みのコントローラで、まず配置だけを直す場合は以下を実行し、ブラウザを強制再読み込みする。秘密値やユーザーデータは変更しない。

```bash
sudo install -d -m 0755 /var/www/ood/public
sudo install -o root -g root -m 0644 \
  /var/www/ood/apps/sys/dashboard/public/files-direct-download.js \
  /var/www/ood/public/files-direct-download.js
```

この処置の後も、配布元を修正版へ更新し、上記のplaybookを再実行する。修正版のビューはキャッシュ回避用の `?v=9` を付けて読み込む。

## REG-031の受入確認を行う

Oracle Linux 8のOOD 4.2.5を中心に、対象ブラウザ・保存先OSごとに以下を確認する。Ubuntuへの配布経路は共通だが、実環境で検証済みとは扱わない。

- 生成済みYAMLと環境変数の優先設定を確認し、容量確認の実効値が300秒であることを確認する。5秒を超えて300秒以内に終わる検証対象で計算が成功し、上限超過時はエラーになること、従来のZIP操作にも同じ設定が適用されることを確認する。
- 単一・複数選択時の合計サイズとファイル数を原本と照合する。回転するアイコンが計算中を示し、計算完了後に名前欄と保存先選択へ切り替わり、同じポップアップ内で転送進捗・完了・エラーが表示されることを確認する。「キャンセル」が計算中・名前確認中・転送中に同じ位置に表示されることも確認する。集計中は保存先を選択できず、キャンセル後に結果が反映されないこと、確認失敗が0バイト表示にならず保存を開始できないことを確認する。
- 単一フォルダが元の名前で二重の階層なく保存されること、複数選択時はポップアップで入力した名前の下に元の名前を保って保存されること、キャンセルとEscでは転送が始まらないこと、同名の場合の連番と不正な入力の拒否を確認する。
- 複数の通常ファイル、フォルダとファイルの混在、入れ子・空フォルダ・隠しファイル・日本語名・空白・`#`・`%`を含む対象を取得し、階層・件数・内容のチェックサムが一致することを確認する。サーバーでZIPを生成しないことも確認する。
- 大きなファイルと0バイトのファイルを取得し、進捗・完了表示と内容を確認する。長いファイル名でもボタンが動かず、ファイル名を表示しないこと、処理中のファイル番号・全ファイル数・平均転送レートが表示されることを確認する。画面を移動・閉じると中断するため、転送中にその操作をしないことを利用者へ案内する。
- 完了後の「閉じる」、計算中・転送中のキャンセル、Escの後に、画面左上へメッセージや空の表示行が残らないことを確認する。
- 中止・通信断・認証期限切れで「保存完了」とならず、完了済みファイルだけが残ることを確認する。再実行が別フォルダへ保存されることを確認する。
- 他ユーザーの領域・許可パス外・読めない項目・サイズ上限超過・シンボリックリンクで取得が拒否されることを確認する。ダウンロード無効時に追加ボタンもスクリプトも表示されないことを確認する。
- Safari・Firefoxなどの未対応環境、HTTP接続、書き込み権限の拒否、保存先OSで使えない名前でエラーが案内されることを確認する。既存の同名ファイルが変更されないことも確認する。
- 開発者ツールのNetworkで `/public/files-direct-download.js?v=9` がJavaScriptとして取得されること、読み込み後にボタンが有効になることを確認する。
- 上部の従来のDownloadと行メニューのDownload、アップロード、通常のファイル閲覧を確認する。role再実行後と画面内のフォルダ移動後にも、追加ボタンが1回だけ動作することを確認する。
